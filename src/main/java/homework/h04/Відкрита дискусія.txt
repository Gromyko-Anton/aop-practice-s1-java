Навіщо в програмуванні окремий тип для «так» і «ні»?
Для того щоб комп'ютер міг миттєво приймати рішення так чи ні працюючи на рівні процесора.

Як сказати !(a && b) людською мовою?
Хоча б одна з умов a чи b не виконується

Чим && відрізняється від &?
&& — це логічне «І», яке миттєво зупиняє перевірку, якщо перша умова хибна, тоді як & — це побітове «І», яке завжди обчислює обидві частини на рівні двійкових нулів та одиниць

Чому програма не падає в if (x != null && x.name == "Іван"), хоча x порожній?
Коли комп'ютер бачить &&, він перевіряє першу умову: x != null. Оскільки x порожній, ця умова відразу дає false
оскільки для загального «І» обов'язково потрібні два «так», комп'ютер розуміє, що фінальний результат усе одно буде негативним, тому він просто ігнорує і не виконує другу частину (x.name == "Іван").

Як запхати 32 відповіді «так/ні» в одне число?
потрібно використати це число як набір із 32 окремих бітів (нулів та одиниць), де кожен біт відповідає за одне «так» (1) або «ні» (0).

Що швидше: n % 2 чи n & 1?
n & 1 працює швидше, ніж n % 2
n % 2 (остача від ділення): Змушує процесор виконувати операцію ділення. Ділення — це найповільніша математична операція на рівні заліза, яка вимагає від процесора багатьох тактів роботи.
n & 1 (побітове І): Комп'ютер просто дивиться на найперший (молодший) біт числа. Якщо там 1 — число непарне, якщо 0 — парне. Це відбувається миттєво за 1 такт процесора.
